🛡️ Production Security Architecture Specification

Enterprise requirements for live government digital service operations

1. Server-Side Phone OTP Authentication

In production, OTPs are generated on the server (`crypto.randomInt(100000, 999999)`), stored with a 5-minute TTL in Redis, and transmitted exclusively via a licensed telecom SMS Gateway (e.g., Twilio, Fast2SMS, or NIC DLT provider). Frontend client code never knows or checks the valid OTP directly.

2. Passwords & Credential Protection

Passwords must be salted and hashed server-side using BCrypt or Argon2 (salt rounds >= 12). Plain-text passwords and hardcoded tokens are never persisted in databases or sent across client logs.

3. Session Management & Storage

Authentication sessions are managed via secure, HttpOnly, SameSite=Strict cookies containing signed JWT or server session IDs. `localStorage` is strictly restricted to non-sensitive UI settings (e.g., dark/light theme, language preference).

4. Atomic Owner Task Assignment

Task acceptance uses database row-level locking (`SELECT ... FOR UPDATE` or atomic Redis lock) to guarantee that when multiple operators attempt to claim a pending citizen application simultaneously, only one succeeds and the other receives a conflict response.

5. Payment Gateway Webhook Verification

Transaction success is never trusted based on client-side returns. The backend verifies cryptographic webhook signatures from the gateway (Razorpay/PayTM/UPI) before shifting an application status to Paid.
